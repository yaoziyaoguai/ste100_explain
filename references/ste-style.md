# STE 风格：规则依据与中文改写

用于校准 `ste100_explain` 的写作约束。正文、图中说明、交互页面解释和旁白采用同一组术语与事实。

## 标准依据与适用边界

本次依据为 [ASD-STE100 Issue 9，2025-01-15](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf)。下表仅概述已核对的选定条文，不代替完整标准。

| 条文 | 相关要求的概述 |
| --- | --- |
| 1.3、1.11 | 限定批准词的含义；同一对象的技术名称保持一致。 |
| 3.6、3.7 | 使用主动语态；说明文仅在执行者未知时允许被动语态。动作优先用批准的动词表达。 |
| 5.1–5.5 | 操作句最多 20 词，使用指令式；每句一项指令，同时动作可合写；必要前提前置；备注只给信息。 |
| 6.3、6.6 | 说明句最多 25 词，每段最多六句。 |
| 第 8 节 | 词数有专门计数规则，不能只依赖空格切分。 |

标准还包含批准词典及技术词的使用规则。词汇限制涉及词义和词性，不能用“都是常见英语单词”替代检查。参见 [ASD 官方 FAQ](https://www.asd-ste100.org/STE_faq.html)。

本技能区分三种使用方式：

- **中文默认解释**：执行主文件中的写作约束。词表取自当前领域和用户材料；句子按动作、条件和判断拆解。这里没有一份所谓“ASD 批准中文词典”。
- **英文启发式解释**：应用可核验的句段、术语和动作规则；未逐词核对批准词典时，不声称符合完整 STE。
- **严格英文 STE**：先取得用户指定版本的完整规则、词典和相关技术词依据，再做词义、词性、句法和计数检查。取得不了资料时，说明缺少哪部分核验，继续交付范围内可完成的草稿。

用户说“80% STE”时，将其理解为文风强度偏好。在中文或英文启发式解释中，保留明确的对象、动作、条件与事实，放松机械的句长目标和指令式节奏。必要时保留较长但结构清楚的句子。不要删掉八成以外的事实，也不要宣称通过了“80% 合规检查”。

不要把某个行业技术词一概换成日常词，也不要把英语的冠词、时态或词数规定机械套到中文。用户需要的是读得懂的准确解释。

## 改写示例

以下均为自拟的中文示例。它们展示本技能的迁移方式，不是 ASD 官方中文示例，也不是某个真实系统的测试结果。

### 1. 用动作说清机制

原文：

> KV cache 通过对已处理 token 的 key 和 value 进行保存，使模型在后续 token 的生成过程中能够实现对这些结果的复用，从而减少重复计算，但会额外占用显存，且缓存大小随序列长度增加。

改写：

> KV cache 保存已处理 token 的 key 和 value。生成后续 token 时，模型复用这些结果，因此可以减少重复计算。KV cache 会额外占用显存。序列越长，缓存越大。

检查点：去掉名词化表达，拆开计算收益与显存代价。不要补写未经测量的速度提升。

### 2. 保持同一对象的名称

原文：

> 请求队列保存尚未执行的请求。这个等待池按到达顺序取出请求。积压缓冲区满时，服务拒绝新请求。

材料前提：这三个名称指的是同一个队列。

改写：

> 请求队列保存尚未执行的请求。请求队列按到达顺序取出请求。请求队列满时，服务拒绝新请求。

检查点：允许有意义的重复。没有“同一个队列”的证据时，先保留三个概念的区别，不能仅为统一术语而合并组件。

### 3. 前置条件，保留条件覆盖范围

原文：

> 如果本次只修改了超时参数且配置校验通过，就先保存配置，再重启服务；其他情况下不要执行这些操作。

改写：

> 仅当以下两个条件都满足时，执行后续步骤：
>
> - 本次只修改了超时参数。
> - 配置校验通过。
>
> 1. 保存配置。
> 2. 重启服务。
>
> 任一条件不满足时，不要执行这两个步骤。

检查点：两个条件都覆盖两个步骤。不要让“重启服务”脱离原文的条件限制。

### 4. 不拆错同时动作

原文：

> 持续按住复位键，同时接通电源。

保留这句话。不要改成“按一下复位键，然后接通电源”。一项指令一句的常规做法，不能改变必须保持的同时关系。

### 5. 不编造执行者

原文：

> 请求已取消。日志未记录取消方。

保留这两句。不能为了使用主动表达改成“客户端取消了请求”或“系统取消了请求”。

### 6. 不把样本结果改成普遍保证

原文：

> 在这次小样本测试中，方案 B 的 p95 延迟比方案 A 低 18%，但测试尚未重复，所以目前还不能确定这个差异是否稳定。

改写：

> 本次测试使用了小样本。方案 B 的 p95 延迟比方案 A 低 18%。测试尚未重复，因此还不能确定这个差异是否稳定。

检查点：保留样本范围、指标、比较对象、数值和不确定性。不要把 p95 延迟改称平均延迟，也不要写成“方案 B 总是快 18%”。

## 如何回查

先比较事实是否保持，再检查表达是否受控。若两个目标暂时冲突，继续拆句或重新组织信息，不牺牲事实来满足句长。

- 沿关键概念检查所有名称，包括图中标签和旁白。
- 沿动作检查执行者、对象、触发条件和先后或同时关系。
- 对照源材料检查数字、否定、范围以及“可能、必须、可以”等词。
- 按说明或操作分别检查句子，再检查段落主题和长度。

这些示例用于校准与人工复核。结构校验只能证明技能文件格式有效，不能证明模型每次输出都遵循这些约束，更不能证明完整 STE 合规。
